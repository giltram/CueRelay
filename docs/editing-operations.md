# 播放头裁剪与字幕拆分

2026-10-24。沿用原 Aegisub 工作区，不新增编辑器、工作区按钮或工具栏。

## 用户操作

个人设置「快捷键」内的「鼠标点击设置字幕边界」默认开启，与既有「保存快捷键」一起保存；「保存显示设置」仅保存音频显示模式，不改动鼠标选项或其未保存输入。关闭后频谱背景左击只 seek 视频，标尺继续 seek；右击背景不改出点。播放/暂停状态、边界拖动、滚轮缩放和平移保留。偏好按账号持久化，通过原 focus/30 秒检查生效，不共享字幕状态。

四个新动作默认均无键位：设置入点为播放头、设置出点为播放头、在播放头位置拆分字幕、在文本光标位置拆分字幕。原默认 G/Enter、S/Space、Q/W/E/D 和删除绑定不变。新动作额外支持 Ctrl/Meta/Alt/Shift + 字母/数字/Enter/Space；冲突沿用共享表的有效绑定校验。例如想把 Q 改为入点，先移除「播放入点前 500ms」的 Q；想用 Enter 拆分文本，先从「提交并下一条」移除 Enter。

- 入出点裁剪读取 video.currentTime，吸附既有 10ms 精度，校验后只更新选中行对应端点及其时间输入。另一端按已应用字幕值保持，不推进字幕或移动视频。非法区间整次拒绝。
- 播放头拆分只接受 text 严格为空的字幕，拆分时间按 10ms 吸附后必须严格位于入出点之间；含文本提示使用文本光标拆分。
- 文本拆分要求字幕 textarea 本身聚焦、选区收拢为光标，光标两侧均有非空白文字。按真实 UTF-16 光标换算 Unicode 字符索引，保留两段原文及空格，不 trim、不复制或丢字。按两侧 Unicode 码点数比例分配原时长，四舍五入到 10ms；分割点落到端点时拒绝，不夹紧或自动拉长。常见组合字符/表情内部位置保护性拒绝。
- 第一版只接受普通文本。整条含 ASS 内联标签、花括号或反斜杠转义（包括 \\N/\\n/\\h）时明确拒绝，不猜测格式标签作用域。非 BMP 字符不能在 UTF-16 代理对内部拆分。
- 两条结果各有新的 `new-<UUIDv4>` 身份，替换原行并选中第一条；文本拆分成功后恢复第一条文本焦点和末尾光标。其他字幕内容和时间、视频播放位置均保持。
- 所有新快捷键遵守工作区可见/会话/媒体校验/只读/导入保护；文本区只特许已配置的文本拆分动作，其他输入框继续保留原生行为。IME、keyCode 229、重复和已处理事件不触发命令；未绑定的 Enter 继续普通换行。

## 保存与明确的协作边界

按用户确认，本次只使用当前整文档快照与项目 revision，不补建字幕锁、审核状态、修改历史或实时推送。因此没有可继承的审核结论，也不虚构审核重置或事件广播。

`ass_format.split_document` 是纯变换，统一验证输入/结果大小、时间与 ASS 格式。`POST /api/ass/split` 用于无持久化本地工作区，不能读取/写入项目；结果仍需导出才保留。项目通过受保护 `POST /api/organizations/:org/projects/:project/split` 调用 `projects.split_cue` → 原 `save_document` 业务入口：User → Organization → Project 锁、重新鉴权、活动状态、revision CAS、固定模板检查，原子保存一次完整快照并增加一次 revision。

项目拆分会一并保存当前已编辑文档和当前行显示的时间草稿（原手动保存方式下无法单独保存一行）。请求期间禁止继续修改和重复拆分；成功响应后才替换工作区文档及 savedRevision。校验、权限、版本冲突或数据库写入失败都不插入本地结果、不清除输入，文本拆分失败还恢复原光标位置；业务失败不改数据库原快照。其他窗口重新加载后看到新快照；已打开窗口继续保留自己的稿件和旧 revision，不能自动覆盖远端结果。

并发拆分、删除快照、编辑保存或归档只有符合 revision 的一个写入成功，其余得到 409。没有通用离线队列或自动重试。网络丢失响应可能发生在数据库提交之后，此时本地仍保留原稿；需要显式重载确认服务端结果，旧 revision 重试不会重复插入。

原始 ASS 行 ID 是模板锚点，无法兼作两条新的 UUID。因此 `Cue` 增加可选 `source_id`，仅允许 new 行引用原模板中的 Dialogue。序列化保留该锚点的 Layer/Name/Margins/Effect，并使用结果行的时间、文字和样式。重复拆分沿用同一锚点；Comment/原模板不变。新行沿既有规则追加到 ASS Events 末尾；工作区仍按时间排序，原有其他行的时间和事件顺序不变。

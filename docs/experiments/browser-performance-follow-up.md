## 删除边界与新发现

评审建议的三个边界已加入 `browser-tests/cue-window-deletion-checks.mjs`，由原 `test:cue-window` 组合运行。当前原实现和修复包均通过：

- 401→400 删除阅读锚点：阅读行交给后继，仍保持窗口化，撤销/重做不丢位置。
- 87px 高行的偏移约 70px，删除后交给 33px 后继：偏移截断到约 32px，相邻内容仍可见，撤销/重做保持。
- 删除尾部锚点及全部后继：最近前驱仍在视口底部，scrollTop 被实际最大滚动范围钳制；不要求前驱成为首个可见行，撤销/重做保持阅读位置。

性能驱动还发现原回归未覆盖的混合行高问题：201 行，编辑首行、搜索、播放和滚动之后，删除离屏首行进入原生模式，同一阅读行 `new-45` 的偏移由 18.5px 变为 15px。单独重跑相同生产场景再次失败；完整基准的三轮也重复出现，并在原生滚动后撤销时把边界处的 `new-50` / 0px 变为 `new-49` / 31px。聚焦 main 前后位置一致，变化发生在阈值切换。普通无媒体混合行高用例未复现这次 3.5px 误差，不能把它当作失败证据；精确操作序列的回归断言保留在性能驱动。

根因是窗口化的 `readAnchor` 使用 scrollTop 与累计高度模型之差，小列表使用真实 DOM 偏移，两者在当前布局中不完全一致。恢复时继续按模型定位，会把该误差带入模式交接。现在两种模式都从已挂载阅读行读取实际偏移，并按行相对 sticky header 的实际位置恢复；目标未挂载才使用模型，在后续测量提交继续校正。短行截断、前驱回退、原生普通布局、阈值、字幕/历史所有权和依赖方向不变。

修复后原失败场景通过，误差不超过 0.5px；完整生产窗口化回归也通过，包括 R1–R4、软换行/宽度/QC、离屏焦点、跨窗口选择、重排和撤销。没有为未证明的风险扩大性能重构。

## 生产性能

运行入口和素材生成方式已归入 [浏览器测试说明](../../frontend/browser-tests/README.md)。`test:browser-performance` 不依赖原本机外部目录，输出生产主包路径及 SHA-256、逐轮两次 RAF 代理、Long Tasks、CDP 布局耗时/次数、脚本耗时与行几何读取次数。所有身份为隔离 HTTP 夹具，字幕序列化和 JASSUB/WASM 为真实本机服务，不写业务数据库或上传视频。

本轮夹具与历史外部驱动不同，不把历史数值直接作为严格基线。原包与修复包固定本轮同一驱动，各测六种规模 × 两档 CPU × 三轮输入/搜索/播放/滚动；201 行另外测三轮删除/原生滚动/撤销。布局耗时是整个阶段的累计量，不是单次 commit，也不是 INP。浏览器测量分开执行，未与其他测试并跑。

## 真实媒体与资源观察

素材只读，位于 Git 忽略的 `local-samples/`。规格：1147.693 秒、439,369,683 字节、1280×720 H.264、AAC 双声道 44.1kHz；对应 ASS 可由原 codec 正常读取，共 168 行。它不是高规格多声道素材。

`test:media-memory` 在生产工作区执行重新选片、远距离 seek、播放、实际选区 Web Audio 试听、隐藏/恢复、关闭字幕、离开页面与释放后等待；通过已有开发探针另测同文件重新选择、分析区间变化和 React 卸载。逐秒通过 CDP 确定本次 Chrome 的进程，再通过 ps 记录 browser/renderer/GPU 等 RSS，原始文件和字幕不进入结果。

首次驱动使用 launchServer/connect，会额外经远程协议传送大文件，因此停止并剔除该轮数据，最终驱动直接启动本机 Chrome。最初同路径换片只实际创建一个 Worker；已在驱动中清空原生 picker 值以保证重新选择触发 change，并断言每轮确实新增一个 Worker、旧 Worker 终止，不把循环次数误报为换片次数。

最终有效运行使用直接启动的 Chrome、修复生产包、20 轮生产流程、20 次开发探针实际换片及最终 60 秒释放观察，总计 276.915 秒，进程退出码 0，无页面错误或意外请求。生产每轮播放两秒并试听首条字幕，不是完整播放整段 19 分钟视频。

- 每轮关闭字幕预览后 Worker 创建/terminate 调用为 3/2，剩余唯一分析 Worker；试听 AudioContext 创建/close 调用为 1/1。分析 cacheBytes 最大 18,570,176，未超过 32MiB。
- 换片探针最终 Worker 创建/terminate 调用为 20/20，卸载断言通过；每次换片均验证新 Worker 代次，避免同路径选择无 change 的假通过。
- RSS 总和初始约 625.4MiB，采样峰值约 1237.7MiB。首轮离页五秒后约 766.8MiB，后 19 轮约 657.5–697.1MiB，未呈单调增长。最终关闭 context、等待 60 秒后约 483.8MiB，进程列表已无 renderer。

这些计数表示 terminate / close 调用，不是原生释放完成证明。RSS 相加可能重复计算共享内存，不是独占物理内存、GPU 显存或 WASM 分配审计，一秒采样也可能遗漏峰值。当前有限观察没有给出持续保留的证据，也不能证明长期无泄漏；没有据此调整缓存预算或增加 Worker。

# 窗口化滚动回归修复（2026-11-08）

针对 [2026-11-07 检查报告](../reviews/browser-performance-2026-11-07.md) 的 R1 / R2。继续保留行级 memo、窗口化、完整搜索/选择数据和原保存协议；本轮没有修改媒体、预览调度、后端或依赖关系。F3 / F6 沿用原报告的待测边界。

## 复现与根因

先把临时探针场景写入 `browser-tests/cue-window-layout-checks.mjs`，由现有 `test:cue-window` 调用。在旧实现上实际执行失败：2000 条连续包含四次换行的字幕，搜索第 1000/1500/400 行及 QC 定位第 1500 行，布局稳定后目标都不在视口；手动滚到列表中段后，隐藏恢复、窗口调宽和列宽变化都改变首个可见行。

R1 是首次挂载就结束 reveal，而新窗口后续测量仍会改变累计高度。R2 是零尺寸隐藏/真实调宽都清空高度，只保留像素 scrollTop 没有保留阅读行。浏览器原生滚动锚定还会与应用校正竞争。

## 实现

- `use-cue-window` 统一拥有逻辑滚动锚点（行 ID / 行内偏移）、待定位目标和布局测量。ResizeObserver 只通知重新测量，行高、累计偏移和滚动校正由同一布局提交编排；新窗口尚有测量变化时保留定位目标，直到对应占位布局稳定后才结束 reveal 和焦点移交。
- 零宽/零高不更新有效布局或清空测量。实际容器宽度/列宽改变才失效缓存，随后以同一行 ID / 行内偏移恢复；行缩短时将偏移限定到该行最后一个可见像素。删除锚点清理其引用。
- 仅窗口化容器禁用原生 `overflow-anchor`，保留一个滚动校正所有者。用户滚动接管锚点；浏览器 focus/scrollIntoView 早于 scroll 事件时，布局提交也识别原生移动，防止旧锚点把鼠标点击目标移走。原跨窗口 Shift 选择/删除/撤销测试验证该事件顺序。
- 纯 `cue-window` 提供偏移、最小 reveal、锚点恢复与有界挂载计算。挂载范围只额外保留校正中的锚点/目标，不全量挂载，不新增依赖、全局状态、轮询或字幕副本。

## R3：跨 200 行阈值的阅读位置交接（2026-11-09）

后续反馈已复验 R1/R2，新增 R3：201 行删除一行后进入原生 200 行模式，用户继续滚动再撤销，窗口化却复用停止监听前的旧锚点。本次保持窗口化阈值、字幕/选择/历史所有权和保存协议，仅修复两种模式的交接。

先加入 `browser-tests/cue-window-threshold-checks.mjs`，由原 `test:cue-window` 调用。修复前实际失败：200 行模式中 `scrollTop=1000`、首个可见行 `new-12`、行内偏移 43px；撤销后跳到 `scrollTop=3378`、`new-46`、偏移 24.5px，与反馈一致。

实现将滚动/尺寸跟踪覆盖两种模式，原生模式用实际 DOM 捕获当前行和偏移，并保留已挂载行的测量供下次窗口化使用。记录已提交渲染模式，在跨阈值时恢复当前阅读锚点；进入原生模式清除窗口化待定位/焦点校正状态。原生模式的普通布局仍不强制恢复锚点，也不因测量缓存更新而额外发起测量提交。零尺寸隐藏保护和 R1/R2 的稳定测量流程保留，未新增依赖或滚动历史。

修复后，同一复现仍显示 `new-12`、43px，撤销后的像素位置为 1033；像素位置可随恢复行与估计高度变化，验收以阅读行 ID / 行内偏移一致为准。新增用例还通过：首次 201→200 删除的阅读交接、滚动后重做回 200、再次滚动并撤销回 201、200 行顶端滚动后撤销，以及重新窗口化后的有界 DOM。偏移误差不超过 0.5px。

## R4：删除阅读锚点时的相邻行交接（2026-11-10）

针对 [交接报告 R4](../reviews/browser-performance-handoff-2026-11-10.md#待修复-r4--p2-删除阅读锚点本身时跨阈值交接失效)。先向 `browser-tests/cue-window-threshold-checks.mjs` 加入原复现场景：201 条连续多行字幕，搜索 `target100end`，滚动到 `new-99` 成为首个可见行、行内偏移约 20px，再删除该行。修复前实际失败：首个可见 ID 变成 `new-58`，scrollTop 仍为 5069，与交接报告一致。

根因是删除清理先丢弃阅读锚点，随后按原像素位置读取已展开的 200 行 DOM，误将远处行接受为新锚点。现在 hook 保留上次提交的行数组引用，在读取新 DOM 前通过纯 `cueAnchorAfterRowsChange` 选择存活后继，无后继再取最近存活前驱；相邻关系以旧顺序判断，不能按新索引猜测。保留行内偏移，由现有恢复逻辑限制到新行高度；无存活邻行时清空。该规则也适用于包含锚点的批量删除，不新增选择耦合、滚动历史、依赖或完整字幕副本，原生小列表普通布局规则保持不变。

修复后的 Chrome 实测（1440×900，等待布局稳定后断言）：

| 场景 | 首个可见 ID | 行内偏移 | scrollTop |
| --- | --- | ---: | ---: |
| 单行删除前 | `new-99` | 20.5px | 5069 |
| 删除后，200 行 | `new-100` | 20px | 8633 |
| 撤销后，201 行 | `new-100` | 20.5px | 8720 |
| 重做后，200 行 | `new-100` | 20px | 8633 |
| 批量删除 `new-98` 至 `new-101` 后，197 行 | `new-102` | 20px | 8546 |
| 批量删除撤销后，201 行 | `new-102` | 20.5px | 8894 |

像素滚动值随实际行高和恢复的行变化，验收以相邻阅读行和行内偏移为准。纯函数测试还覆盖批量跳过已删后继、重排/插入后仍以旧顺序寻找邻行、无后继取前驱、偏移超出行高、空列表、全量替换及空/无效锚点。

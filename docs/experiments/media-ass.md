# 首个媒体 / ASS 验证任务

状态：2026-10-22 已实现本地媒体与无持久化 ASS 验证台，自动检查与合成验证已执行；真实片源与熟练成员制作验收未完成。未进入后续协作里程碑。

## 执行顺序与边界

1. 固定环境依赖，归档用户提供的完整 AGENTS 原文。
2. 纯 `ass_format` 预检、原始记录保留适配与 HTTP 契约测试。
3. 本地 video、10ms 时间网格、行编辑与输入法友好快捷键。
4. JASSUB 本地 WASM/Worker 与用户字体，合成样本浏览器检查。
5. 执行全部自动检查，记录实际结果和人工验证步骤。

未收到真实片源或真实字幕。只创建自有合成样本；不检索用户磁盘寻找私人媒体。

## pysubs2 初始探针

安装 1.8.1 后实际运行 `SSAFile.from_string(...).to_string("ass")`：基础中文、换行、Comment 事件可保留，但分号注释（`Keep this anchor`）丢失，数字格式被规范化。检查当前安装源码还确认读取器固定使用字段表而忽略文件 `Format:` 的字段顺序。

决定：使用小型原始行/事件锚点适配；按文件 Format 映射后再将规范顺序的记录交给 pysubs2 校验。导出只替换 Dialogue 的可编辑字段，其他原始记录保留；不让 pysubs2 重写整份文档。前端不解析或序列化 ASS。

## 样本及来源

- `ass_format/fixtures/basic.ass` 与 `unsupported.ass` 是本任务自行撰写的合成字幕，无第三方片源或真实台词。覆盖中文、英文逗号、强制换行、组合标签、两套样式、重叠行、Comment、辅助字段和分号注释；不支持样本使用 `\pos`。
- 浏览器合成片为 FFmpeg `testsrc2` + 440Hz 正弦音，310 秒、640×360、H.264/yuv420p、25fps CFR、GOP 50、AAC 48kHz，40,450,071 字节。仅临时目录使用，不提交媒体。
- 显示抽检时将合成 ASS 的占位字体名换成 `Arial Unicode MS`，在浏览器选择本机已有 `Arial Unicode.ttf`，Aegisub 使用同一已安装字体；未分发字体文件。
- 页面导入基础 2 行后，通过界面新增 18 行，最后一行结束于 5:00，共 20 条 Dialogue，另保留 1 条 Comment。文本为合成验证用中文。没有声称完成真实对话的听辨打轴或熟练用户试用。

复现合成视频（需自行安装 FFmpeg，输出路径可自行选择）：

```sh
ffmpeg -f lavfi -i testsrc2=size=640x360:rate=25:duration=310 \
  -f lavfi -i sine=frequency=440:sample_rate=48000:duration=310 \
  -c:v libx264 -preset ultrafast -crf 32 -g 50 -pix_fmt yuv420p \
  -c:a aac -b:a 64k -movflags +faststart /tmp/cuerelay-synthetic.mp4
```

调试中实际发现并修复：Vite React preamble 被 CSP 阻止（改为 nonce）；JASSUB 对空字符串 `subContent` 初始化报 `exit(4)`（初始化使用有效源文档，清空调用 `freeTrack`，不传空文档给 setTrack）；pysubs2 丢分号注释（使用保留适配）；DRF JSONParser 直接读流不触发 Django body 大小限制（转换入口先读取受限 body，并补 413 测试）。JASSUB 包引用缺失 source map 的开发警告仍存在，不影响执行。

## 尚未完成与直接执行的人工步骤

当前没有真实片源证据，也没有已知可行性否决；基础合成路径无未解释的功能阻断。以下人工验收缺失意味着 S1 / S3 和整个 M1 尚未通过：

1. 在本机启动两个服务，打开浏览器 Network（保留日志，检查 Worker 请求）。选择字幕组实际固定视频及对应获授权基础 ASS，记录容器 / 编码 / CFR 或 VFR / GOP / 时长 / 浏览器版本 / 硬件。不要将媒体或未授权字幕提交仓库。
2. 熟练成员用实际台词制作至少 5 分钟、20 行。实际使用 I/O、微调、循环、人耳试听、按行定位和中文输入法；记录制作耗时、卡顿、接缝和缺少波形是否阻断，与既有 Aegisub 工作方式比较。
3. 停止循环，展开本机定位测量执行 20 点并保存 JSON，结合已知帧 / 参考时间逐点核对画面稳定耗时和误差。需要完整 S1 门槛时另做 100 随机点和两名熟练成员试用，不把 API 时间输入当作结果。
4. 先导出未修改稿，再修改时间 / 中文 / 样式引用后导出；用 Aegisub 打开，使用同一测试字体抽检，尤其重叠、换行和常用标签。当前只在一个参考帧做了显示抽检，S3 的 20 个渲染对照点仍待完成。
5. 检查 Network 所有请求及本机审计日志，确认无视频 / 音频 / 帧上传和外部字体 / 资源请求。未支持的文件应显示整份拒绝原因，原件下载后比较摘要。
6. 在目标浏览器测试字体缺字 / 回退与单线程降级；当前仅内嵌 Chromium 跨源隔离路径实测。64MiB 的系统 Songti TTC 超过 30MiB 字体上限被明确拒绝，改用 22MiB 的 Arial Unicode TTF 完成合成检查；这不是系统字体全覆盖结论。

# 参考字幕完整浏览：实现与实测（2026-11-23）

## 实现与决策

参考区保留原位置、尺寸调整、展开/收起、纯文本及原生选择复制；现在可以浏览完整参考。主表每次选行（含重复点击）、视频开始/恢复和真实音频试听启动都会定位。手动滚轮、触摸、滚动条、滚动键或选字暂停跟随，后续匹配切换和暂停不抢回浏览位置，下一明确定位恢复。没有新增控件、持久字段或媒体写入。

`matching.ts` 未改：毫秒半开区间、全部重叠、空段、零时长、间隙及真实音频 > 播放视频 > 已应用选区 > 当前视频时钟的优先级继续沿用。没有按主表行号配对。间隙提示作为临时段落放在最近将来参考之前，末尾间隙放在整表之后。

`ReferencePanel → use-reference-window → window` 只在参考模块内组织匹配和几何；EditorWorkbench 仅传一次性定位序号。可视区前后各6行缓冲，远距目标和阅读锚点保留到真实行高稳定。未测行估高，挂载后实际测量；阅读位置为稳定 key 和行内像素。宽度失效旧行高，尺寸变化恢复同一阅读行。同步记录实际写入的 scrollTop，区分程序滚动、布局恢复和用户输入，没有延时忽略窗口。收起移除列表和采样，隐藏断开测量，卸载清理；document.hidden 停止媒体 RAF。

实测促成三处修正：稳定行 ref / ResizeObserver 按尺寸变化通知；间隙移动复用参考索引和基础几何；实测行高以数值后缀差量修正累计偏移，避免每次新行测量重新扫描整份文本/字符串缓存。只在匹配组变化或明确定位时提交匹配 React 更新，未改变已有 matcher。

- 同一 Apple M3 Pro / 18GiB、Darwin 23.6.0、Node 26.4.0、Chrome 147.0.7727.101；生产 Vite build + preview，1440×900、DPR1、CPU rate1；同一进程、每次新 context，无其他浏览器测试并行；每种规模各3轮，轮次交替先运行原版/新版。
- 两版均已加载完整参考数据，媒体和主表相同：30秒、320×180 / 25fps、双声道合成 MP4（508139 bytes，SHA256 见 JSON），100条主字幕。正式 ASS preview 统一以 HTTP fixture 返回不可用；真实视频、音频分析/解码仍运行。无数据库写入或真实项目数据。
- 500 条 SRT 为 64383 bytes；5000 条为 656351 bytes。均通过真实 `srt_format.parse_reference_srt`，遵守现有 5000 条 / 1MiB 上限；含软/硬换行、重叠、间隙、空段、零时长。5000条集中在25秒内（约200条/秒），是高频匹配压力夹具，并非典型人类字幕节奏。
- 展开：数据已加载后首次重新挂载列表；远距定位：主表第51条（12.5秒）。延迟使用浏览器 performance.now，从实际 click 到匹配出现在视口内，再等待两次 RAF。数值受本机约8.33ms RAF周期量化，1–2ms差异不应作显著快慢结论。
- 滚动：90次相同±80px、每次间隔两帧，约1.5秒。原版只有附近匹配，不能浏览整份，因此重放相同输入时实际移动距离不同；新增滚动成本不是等量业务工作的回退。
- 播放：真实视频连续3秒；另在参考收起时重放同段3秒，区分工作区背景成本与参考增量。CDP `Performance` 差值记录 TaskDuration、ScriptDuration、LayoutDuration；页面 PerformanceObserver 记录 ≥50ms 长任务，RAF 记录帧间隔、>25ms次数。Task包含工作区媒体/绘制等总主线程成本；Script更直接反映本次计算/React成本，二者不能相加。
- 本机原生音频输出不可用时 AudioContext 虽 running 但 currentTime 停在0.0053s。Chrome `--disable-audio-output` 后原生时钟0.5秒内推进约0.49秒；两版最终比较统一使用该参数及 `--autoplay-policy=no-user-gesture-required`。功能测试仍用真实 AudioContext/PCM/position getter，未用假时钟；听感未测。

本次新版参考段落最多挂载18个（含缓冲/保留锚点），收起为0；原版远距选区匹配时为6/43个。数据仍为500/5000条完整集合。测试不是内存测量，也不是弱设备帧率保证。

## 复现

原版源代码应导出到临时目录，避免覆盖工作区；例如从上述基线提交 `git archive` 解包，复用相同 `frontend/node_modules` 和 `.open-source-cache`，在该副本 `frontend` 执行 `npm run build`。本次已在实现前保存原版构建，不需要回滚工作区。

在两个终端启动相同生产 preview（使用各自 build 输出）：

```sh
cd frontend
npm run build -- --outDir /private/tmp/cuerelay-reference-after/dist
npm run preview -- --outDir /private/tmp/cuerelay-reference-baseline/dist --port 5281
# 另一个终端
npm run preview -- --outDir /private/tmp/cuerelay-reference-after/dist --port 5282
```

再在 `frontend` 运行：

```sh
npm run test:reference-scroll
REFERENCE_LAYOUT_URL=http://127.0.0.1:5282 npm run test:reference-layout
REFERENCE_PERF_OUTPUT=/private/tmp/reference-performance.json npm run test:reference-performance
npm run test -- --run --exclude 'platform-tests/**'
npm run typecheck
npm run build
```

可用 `REFERENCE_PERF_COUNTS`、`REFERENCE_PERF_ROUNDS` 和 `REFERENCE_PERF_URLS` 控制规模/重复次数/两版地址；最终报告默认500,5000 / 3轮。测量脚本不设置通过/失败性能阈值，不将合成数据推断为真实设备保证。

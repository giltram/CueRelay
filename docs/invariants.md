# 业务不变量与验证责任

状态：Planning 基线；样式管理 A 阶段已实现快照内的 I03/I05/I06/I08 部分，完整事件/租约/审核机制仍未实现，具体覆盖见 [样式管理](style-management.md)。本文件是约束清单，实体含义见 [领域模型](domain-model.md)，协议细节见 [实时协议](realtime-protocol.md)。约束须在服务端命令边界执行，前端校验用于反馈，不能成为唯一保障。表格包含后续完整协作的验证要求；样式切片已执行覆盖见样式管理契约，未实现项不能视为通过。

## 1. 永远成立的约束

| ID | 不变量 | 强制边界与关键反例 |
| --- | --- | --- |
| I01 | 一个项目只有一个固定的媒体时间基准；媒体内容、帧、音频及波形采样不会通过正常编辑或遥测上传 | 前端 media 仅输出允许元数据；抓包和第三方组件网络审计；不得把波形生成失败降级成云端处理 |
| I02 | 哈希一致性判断使用全文件 SHA-256 与大小；不同文件不得被快速预检标记为严格通过 | 本地增量哈希；同大小不同内容/不同分块长度测试；客户端声明不能用作权限证明 |
| I03 | 任意项目读写都要求当前活动成员身份和对应能力；请求中的对象必须属于该项目 | HTTP、WS 连接/每条命令/每次数据发送与重放均鉴权；跨项目 cue/style/review/source ID 组合攻击测试 |
| I04 | 成员能力可叠加，项目至少有一个管理员；撤权、归档使相应租约失效 | 项目事务锁内变更权限；两管理员同时互相撤权只能成功一方；归档中不再接受编辑 |
| I05 | 活动行有稳定 ID、合法时间和本项目样式；`0 ≤ start < end`，时间为整数且按 10ms 对齐 | 数据库检查约束/外键与命令校验；负数、零时长、跨项目样式、导入缺失引用必须拒绝；重叠不违规 |
| I06 | 行的已知与未知 ASS 数据不得被静默丢弃或改写；项目样式不能被任意行标签绕过 | 格式预检、文本写入验证、原件保留与能力表；未知标签/附件走整份保护性路径；语义往返样例测试 |
| I07 | 同一行最多一个有效租约；写入/删除/提交/审核必须同时满足所有者会话、token、未过期、权限和项目可写 | PostgreSQL 租约记录与服务器时间；双进程同时取锁、旧 token 延迟续期/释放/保存必须失败 |
| I08 | 租约只是编辑意图保护；每次更新还必须检查预期 cue_version，项目级操作还须检查对应版本 | 事务内乐观并发控制；旧页面、第二标签页、迟到请求不能静默覆盖新版本 |
| I09 | 每次持久变更、版本递增、变更日志和成功幂等回执要么一起提交，要么一起回滚 | 同一 PostgreSQL 事务；在各写入点注入异常，不能出现数据已变但历史/序号缺失 |
| I10 | 同一项目成功持久变更有连续且唯一的 project_seq；一个原子多对象操作只有一个序号 | 所有命令先锁 Project 行；数据库唯一 `(project,seq)`；普通租约生命周期/在线状态不进入此序列，显式管理员撤锁审计进入 |
| I11 | 相同用户、项目、命令 ID 和相同请求内容最多产生一次持久效果；不同请求不能复用 ID；客户端跨刷新仍能定位未决命令 | 服务端成功回执与请求指纹；客户端发送前持久化命令 ID、冻结请求及草稿关联，落盘失败不发送；丢确认后关闭/重开，不能换 ID 重建或换 token 重投原 ID |
| I12 | 客户端只能把数据库已提交的明确结果标为“已保存”；网络错误表示结果未知，不等于失败 | 命令回执/命令状态查询；提交成功后断连接、ACK 乱序测试；不能拿“已发送”代替确认 |
| I13 | 视觉 Review 必须绑定当前 cue_version、style_revision 与媒体摘要；只允许检查当前已提交版本；内容审核独立保留 | 同一事务验证、追加不可变 Review；同时改时间/文本/样式与批准时，不得产生对新内容有效的旧批准 |
| I14 | 行字段变更使旧翻译提交和审核失效；样式/渲染设置变更仅使旧视觉 QC 失效，不撤销内容审核或翻译提交；旧记录不被篡改 | 派生状态计算；直接修改文本、只改时间、样式统一更新、自审路径均覆盖 |
| I15 | 删除不抹掉可追踪历史，不允许迟到消息自动复活；恢复不回拨版本、不继承旧审核 | 软删除和追加日志；删除与保存竞争、P1 拆并/恢复多对象事务测试 |
| I16 | 共享状态以 PostgreSQL 为权威；Redis/WS/客户端副本缺失不能造成权威数据丢失 | 重放/一致快照和周期水位校验；Redis 重启、尾事件丢失、重连并发写入故障测试 |
| I17 | 应用持久事件必须连续，缺口不能跳过；快照包含同一时点的行、样式、审核和项目序号 | 客户端连续游标与服务器一致快照；乱序、重复、导入大事件、快照期间写入测试 |
| I18 | 导入原子且只进空项目；导出来自一致快照；原始文件下载与编辑后导出有不同保真承诺 | 预检报告绑定摘要与版本；预检后项目被修改应拒绝；不能输出新样式配旧行的混合文件 |
| I19 | 锁过期、冲突、断网、校验错误不能静默清空尚未提交的本地草稿；同账号多标签页的草稿独立；草稿不能自动覆盖共享新版本 | 独立 draft_id/代次与多候选恢复；ACK 仅确认关联草稿代次，不删除其他实例或更高代次输入；双标签页断网/过期/刷新、旧 ACK、配额不足与删除冲突测试 |

## 2. 约束的事务落点

除新项目的原子初始化外，所有项目持久命令和租约命令遵守同一个锁顺序：先 Project，随后涉及的 cue/lease 按稳定 ID 排序。P0 为小组规模主动选择每项目短事务串行写入，避免样式、权限、审核各自加锁产生交叉竞态。项目之间可并发，不在事务里解析媒体、等待网络或进行大文件哈希。

命令事务先检查当前身份与项目查看权限，再查询成功幂等回执：已成功的同载荷请求返回原回执，无需仍持有旧租约或原编辑能力；未成功的新请求必须检查当前命令能力及全部前置条件。已被撤销查看权限的成员不能通过命令 ID 读取旧数据。权限变更、显式管理员撤锁也必须走同一入口，禁止后台管理页面绕过这些规则直接改业务字段。

数据库应承担可表达的非负时间/时间网格/唯一性/外键约束；跨对象规则和版本有效性由清晰命令实现。不要把数据库事务变成一把长时间持有的用户编辑锁，也不要只靠 Redis TTL 保证 I07。

I11/I17 的版本与回执比较不能跨数据库恢复产生的不同历史直接复用；恢复后必须识别旧客户端并使旧缓存、租约及自动重试失效。[D-R1](decisions/0001-initial-architecture.md#d-r1) 已选择显式恢复代号，细节与验收在相关恢复机制开发时落实；不能仅用序号相等宣称满足恢复正确性。本约束不要求首个本地媒体/ASS 验证任务提前实现恢复机制。

## 3. 有意不保证的事项

- 不保证未被服务器确认、且本地持久化也失败的草稿能跨设备或浏览器清理恢复。明确区分“浏览器草稿”与“服务端已保存”。
- 不保证字符级无冲突自动合并、离线无缝继续写入、任意浏览器/编码均可精确逐帧。
- 不把单行批准描述为整个上下文或整片批准。相邻行修改仍需人工通看。
- 已发送给合法成员的内容不能在撤权后收回；撤权保证禁止之后的命令与后续发送，关闭连接有有界延迟。
- 不承诺高级 ASS 的可编辑保真；保护性拒绝优于未经证明的重写。

## 4. 测试分工

格式/时间/状态派生使用纯逻辑样例测试；权限、行租约、序号与幂等使用真实 PostgreSQL 多连接事务测试；WS 补齐使用协议与故障注入测试；媒体隐私与三人工序使用独立浏览器端到端验收。SQLite 或单线程 mock 不能证明租约与事务竞争正确。

任务完成时依据这些 ID 报告覆盖与未覆盖项，不复制一套工程规范。边界与依赖由 [架构入口](architecture.md) 管理，实施顺序由 [里程碑](milestones.md) 管理。

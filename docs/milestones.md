# 里程碑、风险实验与任务拆分

状态：路线图；2026-10-22 已实施第 5 节首个有限切片，自动检查与合成验证见 [实验记录](experiments/media-ass.md)，真实片源验收仍待执行。其余实验 / 里程碑尚未实施。工程原则遵循 `AGENTS.md`。

Planning Review 已结束，用户已确认并授权第 5 节首个 Coding Task。当前只推进播放、打轴和 ASS 往返；未实施后续协作切片或复杂恢复。

## 1. 顺序与范围

保留 M0–M4 五个阶段，但调整原先“完整单人编辑器后再做协作”的顺序：M1 验证同步/事务前提，M2 直接交付三人薄闭环，M3 扩充实际编辑与格式覆盖，M4 硬化并内部 Alpha。每个阶段有端到端切片，不能以外围 UI 完成度代替核心协作验收。

所有数值是待实测校准的门槛；调整需记录测量、理由和替代验收。每个实验输出样本清单、环境/版本、原始测量、结论和 go/no-go，不能以“演示能运行”作为通过。当前没有工期承诺，待 M1 后估算；波形/编码的结论可能改变范围。

## 2. Technical Spikes

### S1：本地片源、时间定位与打轴体验（最高优先级）

**风险**：容器/编码不兼容，原生 seek 不满足定位精度，VFR/长 GOP 无法可靠逐帧，文件句柄刷新后失效。

**实验**：先用团队实际使用的代表性片源验证播放和制作，再根据实际格式扩充支持矩阵；不要求首个任务穷尽 MP4/MKV、HEVC、CFR/VFR、长 GOP 等所有组合。准备带可识别帧号/已知时间点的合成参考片；记录浏览器/OS/CPU/内存/存储。比较时间输入、微调、seeked、帧回调时间、音画叠加与循环试听；后续再覆盖长片及权限生命周期。

**通过门槛**：

- 为每种实际片源给出可播放/不可播放矩阵及清晰错误路径；不能用只测扩展名代替编码测试。
- 在拟支持的参考配置上，100 个随机定位点 p95 稳定画面时间 ≤300ms，已知参考点误差 ≤一帧；说明测量的是媒体时间还是实际呈现帧。若不满足，应明确禁止“精确逐帧”宣传并让熟练打轴人员判定是否阻断。
- 至少两名熟练成员各制作 5 分钟代表性片段，能用快捷键设置/微调入出点、循环试听、回看上下文，无输入法误触，无阻断问题；记录单位片段耗时与桌面现有方法对比，作为是否补波形/逐帧的证据，不凭主观开发者判断。
- 全程抓包没有媒体字节/帧/音频上传，刷新与校验失败能重新选择且不损坏字幕。

**不通过时**：先评估缩小支持片源范围是否仍服务真实用户；若必须支持浏览器无法解码的基准片源，提交本地解复用/解码或受控统一代理片源方案及时间坐标验证成本，开发者决定后再推进。不能自动转到服务器转码，也不能让成员各自换片而不重建基准。

### S2：大文件完整哈希与本地波形预算

**风险**：原生 digest 非流式；整段音频解码内存随时长增长；长片生成波形可能比编辑本身还重。

**实验**：Worker 固定块顺序增量 SHA-256，对 100MB、2GB、10GB 文件（包含实际样本）比较本机独立完整摘要，测试随机块边界、取消、文件不可读、后台切换。波形先测候选库的解码内存，再评估本地分段峰值生成与缓存，区分容器解复用、解码与显示三个成本；不要把截断压缩字节块当成可独立解码音频片段。

**通过门槛**：

- 不同块长均得到相同标准文件摘要；同大小不同内容检测失败；初步以 4MiB 块、至多两个在途块评估，哈希增量内存目标 ≤128MiB 且不随文件大小线性增长。
- 参考 SSD/开发机目标吞吐 ≥100MiB/s，10GB 有明确进度；取消响应 ≤1 秒，哈希时编辑交互 p95 ≤100ms。低于预算应报告实际预计等待时间并决定产品是否可接受，不能以静默部分哈希通过。
- 波形分项仅在 S1 判定基础波形为 P0 必需时成为 M2 前置验收；否则记录 P1 延后结论，不要求先完成长视频波形方案。若执行，对 2 小时片源记录准备时间、峰值内存、播放负载和时间对齐误差；初步目标额外内存 ≤512MiB、2 分钟内有可用峰值、参考点偏差 ≤20ms。峰值只能留本地，缓存按媒体摘要/算法版本隔离，可删除，失败不影响已保存字幕。

**决策门槛**：若 S1 证明无波形也可完成基础制作，波形留 P1；若不可接受，则有限的点击定位/区间波形升 P0。若长视频纯浏览器方案无法达标，先报告能力限制、外部本地生成峰值的操作成本或重新评估客户端形态，不能在正常编辑中上传音频作为补丁。哈希与波形测量分开，不能把视频解码内存计入“恒定哈希内存”来混淆结论。

### S3：ASS 可编辑子集、往返与渲染

**风险**：解析器丢未知信息、Text 逗号/标签转义错误、事件排序改变重叠效果、字体/样式显示不一致。

**实验**：先以真实基础 ASS 和少量合成/脱敏金样本验证时间、中文、换行、样式与导出，再随实现覆盖 [能力表](domain-model.md) 的其余字段、Comment、元数据和格式边界；首个任务只需代表性不支持内容的保护性拒绝，不先穷尽附件、极限时间、恶意输入等矩阵。比较候选解析器与小型保留适配，评估 JASSUB/libass 的本地渲染、字体与网络行为。

**通过门槛**：

- 受支持样本 `导入→不修改→导出→再导入` 后，时间、文本、样式、辅助字段、注释及事件次序语义相同；原件下载摘要完全相同。
- 逐个修改时间/文本/样式后，仅预期语义变化；至少 20 个代表性时间点用同一测试字体与 Aegisub/libass 参考渲染比对，字体缺失有可见提示，不能拿 CSS 普通字幕近似当作 ASS 一致显示。
- 每个不支持样本给出文件/行号和原因；可编辑导入全部拒绝，无部分写入，无未知数据损失；解析/渲染不触发外部 URL 或本地路径读取。
- 确认候选发行包维护情况、许可证/传递依赖及跨源隔离/单线程行为，留下采用或否决结论。

**不通过时**：缩减“可编辑”支持面或增加明确格式适配；原件保护要求不能降低。若真实字幕普遍包含受限标签，应先由开发者确认子集扩展，而不是假定那些字幕不重要。

### S4：协作一致性、租约与恢复

**风险**：并发覆盖、租约过期后旧请求写入、重复执行、审核绑定错误、提交后推送失败、尾事件丢失、撤权后连接继续读。

**实验**：真实 PostgreSQL 多连接/多个服务进程；三独立浏览器或自动化隔离会话；可控网络中断、重复/乱序/丢事件、提交后丢 ACK、杀死应用进程、Redis 重启；并发修改样式/审核、撤权/保存、取锁/删除。分批在 M1 验证核心前提、M2 验证薄闭环、M4 覆盖完整矩阵。

**通过门槛**：

- M1：两个进程竞争同一租约和版本，最多一个写入成功；同 ID 重试无重复效果；数据库回滚不产生事件或序号缺口。项目创建、空轴创建和行保存须分别在“未决记录落盘后未发送／服务端提交但未收到确认／收到确认但未本地清理”处关闭重开客户端，保持原命令身份，无重复效果、不丢新输入；本地记录落盘失败不得发送。
- M2：打轴创建后翻译立即收到并提交，校对批准；再修改时间使原审核失效；提交后丢 ACK 可查到原回执；掉最后一条事件也能 ≤10 秒发现并恢复。同账号同浏览器双标签页中 A 断网留草稿、租约到期后 B 保存，再刷新两页，草稿候选独立；旧 ACK 不清理另一草稿或更高代次，失效 token 不被替换后复用旧命令 ID。
- M4：在 10 人、5,000 行、5 个持久命令/秒、RTT ≤100ms 的参考环境持续 10 分钟，p95 推送 ≤500ms；重复命令 100 次只产生一次效果；100 轮关键竞争无静默覆盖或错误批准。重连后与权威快照逐字段比对一致，撤权后新命令立即拒绝、连接 ≤10 秒关闭。
- 广播失败与应用重启不丢已确认数据；锁无人续期时在 45 秒 TTL 后能重新取得；旧 token 的迟到保存/续期/释放全部拒绝。若数据库锁等待超出保存预算，记录热点再决定细化锁粒度，不能跳过版本检查换吞吐。
- M4 备份恢复验收必须包含：旧客户端离线后恢复到较早状态，新历史重新增长至旧游标相同及更大序号，再唤醒客户端。旧缓存须全量更新，旧会话/租约不得写入，旧未决命令不得自动作用于新历史；采用 [D-R1](decisions/0001-initial-architecture.md#d-r1) 已确认的恢复代号方案，相关机制开发时实现，不阻塞首个验证任务。

## 3. Milestones

### M0：Repository Foundation

- **目标/范围**：开发者审阅并确认设计边界后，建立可逐步实现的最小工程基础；将会话中的 `AGENTS.md` 原文归档为权威文件。选择相容、受维护且许可明确的版本，建立最小 Django/React 启动与测试入口；不预建所有未来模块。
- **依赖**：设计默认已确认；首个验证任务准备实际视频/ASS 样本及参考浏览器，登录与部署细节在相关功能开发时落实。
- **交付**：工程结构、运行/测试说明、最小认证约定和测试夹具、依赖/许可证选择记录；实际代码出现后更新架构入口与局部 README。
- **验收**：新 Agent 仅从仓库说明可运行最小 smoke test；可定位公开业务入口；没有业务逆向依赖或空壳通用框架。
- **核心风险**：一次性脚手架过多、版本不相容、尚未验证就选定媒体组件。
- **任务**：M0.1 归档指令与已确认决策；M0.2 最小服务/页面与测试；M0.3 记录实际入口和测试命令。D-R1 已选择 A，其实现延后到相关恢复机制开发阶段。首个任务范围见第 5 节，不预建其他业务模块或配置 Docker/CI。

### M1：高风险可行性与最小贯通

- **目标/范围**：先证明本地媒体、ASS 和并发方案可行；以最简页面/命令验证“空轴写入数据库→另一个会话收到”。不追求完整编辑 UI。
- **依赖**：M0；有真实样本与熟练成员参加 S1。
- **交付**：S1/S3 结果、S2 哈希结果及波形执行或 P1 延后结论，S4 的核心事务与恢复前提报告；被选中的小型实现应进入对应公共模块，实验性对照代码有明确位置和用途，避免形成第二套业务实现。
- **验收**：列出每个支持/不支持组合与采用决定；2GB/10GB 哈希完整正确；金样本不会静默损坏；两个独立会话能观察同一个持久空轴；成功日志与回执可查。无法通过的高风险项有开发者决策，不以假通过进入 M2。
- **核心风险**：熟练人员不可接受的打轴体验、常用片源不可播、ASS 子集不适配实际文件。
- **任务**：M1.1 片源/时间交互切片；M1.2 哈希与条件性波形预算；M1.3 ASS 金样本及格式适配；M1.4 Project 事务、租约、幂等与 WS 通知薄切片，验收采用 S4/M1 的跨关闭重开案例。任务按依赖顺序实施，无需多 Agent 并发。

### M2：三人工序协作薄闭环

- **目标/范围**：三个真实身份登录/项目授权、本地校验、统一默认样式、创建空轴、整行租约、译文保存/提交、单行审核、最小历史、一致快照/事件补齐、工作稿/交付导出已验证的 ASS 样例。
- **依赖**：M1 的关键 go/no-go 已解决；版本/回执/状态派生契约稳定。
- **交付**：一段可连续工作的端到端流水线；公共命令、协议契约测试和三浏览器验收记录。仍可采用简单布局，但不能用假用户、内存字幕或模拟推送代替闭环。
- **验收**：三名成员各加载同片，至少 20 行中存在打轴/翻译/校对同时工作；保存确认跨刷新保留；改已批准行使审核失效；无锁/旧版本写入被拒；丢 ACK/掉线恢复正确；导出在参考播放器中打开。
- **核心风险**：保存与提交混淆、过长持锁阻塞流水线、协议与 UI 草稿状态不一致。
- **任务**：M2.1 账号/项目权限端到端；M2.2 空轴/租约/保存确认；M2.3 翻译队列与显式提交；M2.4 审核绑定与历史；M2.5 订阅/快照/重放/草稿冲突；M2.6 默认样式与导出。M2.2/M2.5 必须覆盖 S4/M2 的双标签页隔离、ACK 清理与未决命令恢复。每个任务同时包含后端规则、所需 UI 和相应反例测试。

### M3：实际编辑与完整 P0 格式范围

- **目标/范围**：把薄闭环打磨到实际字幕制作：时间输入/微调/入出点/循环试听、字幕叠加、完整基础快捷键、按时间上下文列表、样式管理、ASS 预检/空项目导入/原件保护与能力表全部支持项、删除与基础历史视图。S1 认定必需的有限波形纳入本阶段。
- **依赖**：M2 闭环通过，M1 明确可编辑 ASS 与媒体能力范围。
- **交付**：覆盖 [F01–F10](product.md) 的功能清单、格式金样本回归、熟练用户试用记录；清楚区分仍属 P1 的增强。
- **验收**：真实片段不依赖文本编辑器或 ASS 文件合并；样式更新使旧批准失效；不可编辑文件保护性拒绝且可取得原件；导入期间竞争写入不会部分成功；导出来自同一快照。打轴体验达到 S1 确认的底线。
- **核心风险**：UI 快捷键/输入法冲突、样式与字体差异、预览与导出不一致。
- **任务**：M3.1 时间与键盘切片；M3.2 样式修改与全项目审核失效；M3.3 格式能力表与导入保护；M3.4 删除/历史与上下文；M3.5 用户阻断反馈修正。拆并、用户评论和恢复 UI 留 P1，不混入格式加固。

### M4：一致性加固与 Internal Alpha

- **目标/范围**：完整 S4 故障矩阵、跨项目安全/撤权、媒体网络审计、性能预算、数据库备份恢复、真实 100 行闭环与交付质量。不是在此阶段才首次实现断线正确性。
- **依赖**：M3 的 P0 功能已完成；有部署/备份环境和明确测试配置。
- **交付**：不变量覆盖表、容量与故障报告、已知限制/支持矩阵、恢复演练、Alpha 验收记录与下一批有优先级的 P1 任务。
- **验收**：达到 [产品成功标准](product.md) 和 S4 门槛；未关闭的阻断问题不得以 P1 标记绕过；能恢复数据库并核对已确认字幕/历史；记录实际 RPO/RTO，不编造 SLA。无媒体内容出网，无未授权后续读写。
- **核心风险**：偶现竞争、数据库项目锁热点、后台标签页/浏览器缓存与真实使用不符。
- **任务**：M4.1 竞争与断线矩阵；M4.2 容量/浏览器内存与可见性切换；M4.3 认证/授权/ASS 输入/网络审计；M4.4 备份恢复及真实小组验收，包含 S4/M4 的相同/更大游标旧客户端案例。

## 4. 面向后续 Agent 的任务契约

每个实现任务应在任务正文中写清：用户可观察结果；涉及模块和具名公共命令；相关 Ixx；前置版本/输入；成功与失败输出；需要变更的文档；实际可执行的验收命令与人工检查。先读这些契约再扩展依赖，不让未来 Agent 从聊天猜规则。

首个 Coding Task 先执行第 5 节的媒体/ASS 验证切片。随后仍按 M1.4/M2 进入首个协作业务切片：“有 timing 权限的成员创建一条空轴，另一成员实时看到，刷新仍存在”，贯穿授权、数据库事务、序号/回执、推送与副本补齐；媒体验证通过后不继续扩建大型单人编辑器。

业务测试围绕边界反例编写，不复制实现；依赖检查针对 [架构允许图](architecture.md)，私有 ORM 仅 projects 内访问。发生接口变更时在同任务更新协议/领域/测试，必要时追加 ADR；当前没有使用场景的 Repository、CRDT 或通用工作流任务不要加入 backlog。

## 5. 第一个 Coding Task：最小工程骨架与媒体 / ASS 验证台

### 依赖

- 环境：Python、Node.js/npm，以及一个实际可用的桌面浏览器；编码时核对兼容版本并固定，不在本轮安装。
- 后端：Django、DRF、pysubs2（先通过样本检验其保留行为，适配局限留在 ass_format）。测试使用 Django/unittest，不额外引入后端测试框架。
- 前端：React、React DOM、TypeScript、Vite、React Vite 插件、相应类型包；Vitest 用于时间逻辑测试，JASSUB 用于 ASS 预览。具体版本及 WASM/字体资源在实施时核对并本地提供，不自动请求远程字体。
- 本任务不连接 PostgreSQL/Redis，也不引入替代业务存储；协作模块开发时再接入已规划的基础设施。
- 输入：至少一份字幕组典型本地视频及对应基础 ASS，可先用合成样本开发；未取得真实样本时只能报告合成样本结果，不能宣称真实片源验证通过。

### 验证方式与完成标准

- 自动检查：后端运行 `python manage.py check`、`python manage.py test ass_format http_api`；前端运行 `npm run typecheck`、`npm run test -- --run`、`npm run build`。覆盖时间网格/零长度拒绝、中文/换行/样式往返和不支持内容拒绝，避免铺开完整故障矩阵。
- 浏览器操作：加载一份典型真实片源，完成至少 5 分钟、20 行的制作，实际使用快捷键、入出点、微调、循环试听和字幕定位；记录卡顿、精度与缺少波形是否阻断。首轮抽测至少 20 个时间点并记录寻址到画面稳定耗时及已知参考点误差，不以时间输入成功宣称逐帧可靠。
- ASS 交付：导入→不修改导出→重新解析的基础字段语义相同；修改后的文本/时间正确保留，导出可由 Aegisub 打开，并用同一测试字体抽检显示；不支持输入有明确原因且原件可取得。
- 网络检查：浏览器请求中没有视频、音频或帧数据；ASS 转换只传字幕内容，第三方渲染器不产生意外外部请求。
- 完成：上述检查实际执行并留记录，新开发者可按 README 启动复现；真实试用没有未解释的阻断问题，或已有明确的可行性否决结论及证据。若真实片源无法满足基础制作，停止扩建并报告，不能以脚手架启动成功代替验证通过。

完成本任务后停止。M1 其余验证及早期协作切片需后续任务授权，本任务不自动进入。

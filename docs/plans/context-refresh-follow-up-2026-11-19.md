# 上下文刷新补充反馈

范围：首页本地入口的草稿范围、较新 503 遮蔽撤权、持续刷新阻塞首次项目列表、账号切换后慢设置阻塞明确放弃的草稿清理、成功身份确认后迟到 401 重开登录框。

执行计划：

1. 用延迟 HTTP 与真实 IndexedDB 分别复现五项反馈，保留上轮四组回归。
2. 将成功数据的版本与刷新反馈的版本分开。暂时失败只更新错误，不作废有效数据；成功撤权或权限拒绝是有序的权威结果。项目同查询允许在途响应推进，切查询/账号/可用性时才作废旧请求。
3. 账号接纳完成即返回；组织和个人设置在后台加载，不参与明确放弃的草稿处理。
4. 仅在没有后续成功身份确认时，允许旧请求的认证错误使会话失效；当前真实认证失败保持原行为。
5. 用户已确认：首页等待默认组织确定后开放本地入口。显式组织入口及已确认无组织的入口保持可用；首次组织读取失败时保持禁用，正常重试成功后开放。
6. 运行定向浏览器、单元、类型、构建和原有回归，更新架构契约与执行结果。

实现：新增无外部依赖的 request-state/ReadOrder，由 App 与 ProjectsPanel 共用数据/反馈两个独立版本，调用方继续拥有账号 epoch 和查询生命周期。成功数据/权威拒绝推进数据版本，503 等暂时失败仅推进反馈版本，解决两处相同的版本混用问题。账号客户端以请求发出时的成功身份确认版本过滤过期认证失败，不依赖资源 UI 的错误过滤来防止失效副作用。没有改 HTTP API、数据结构或持久化；首页入口只有必要的原位禁用状态。

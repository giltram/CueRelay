# 工作区状态与列表响应补充修复

范围：旧项目成功响应清除已生效撤权、唯一列表请求被 supersede 后加载不结束、旧总数过早回退分页、工作区展示迟到 401 的预期 request_superseded。

计划：

1. 用真实 App、合成媒体及可控响应分别复现四项，先建立只读/草稿/媒体保留的断言。
2. 为同一工作区的权限/归档状态建立明确顺序，拒绝旧状态覆盖较新的撤权，保留真正较新成功检查的恢复能力；预期取消不展示为业务错误。
3. 列表请求的收尾与数据/反馈接纳独立，分页校正只采用没有更新检查在途的结果；正常数据仍可提前显示。
4. 运行新旧浏览器回归、单测、类型/构建、真实后端 E2E 和双语布局；同步模块与架构文档。

实现：app-workspace 为同一账号/项目的路由读取、显式 reload、轮询共用状态顺序；明确拒绝推进状态版本，旧成功不能解除只读，过期 reload 返回 false，避免 App 据此删除保留的草稿。后台的预期 request_superseded 不再发给全局错误出口，初次读取被取代时重新请求当前资源。ProjectsPanel 的 pending 计数独立于结果接纳，所有路径在 finally 收尾；ReadOrder.isLatest 只约束自动页码校正，不阻止较早有效行数据先显示。

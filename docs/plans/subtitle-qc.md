# 自动字幕质量检查：执行计划

2026-11-07。用户已确认字幕区右侧按需显示 QC、30% / 320–480px 宽度、左侧约 740px 下限及窄屏临时切换，授权开始实现。实现入口和最终契约见 frontend/src/subtitle-qc/README.md、workspace-ui/README.md；验证见 docs/experiments/subtitle-qc.md。

## 现有事实

- `workspace-ui/use-edit-history` 唯一拥有内存文档、选择和原始时间草稿。正文及样式修改直接进入内存文档；时间草稿须提交后才进入保存/导出快照。
- `EditorWorkbench.selectCueFromTable` 已处理按 ID 选行、试听取消、视频暂停与入点定位。同一行重选保留时间草稿；真正换行沿用现有草稿处理。
- `ResizableWorkbench` 已提供 media/editor/subtitles 插槽。桌面下方字幕区填充剩余高度，最小 144px；900px 以下改为纵向布局，字幕列表高 320px。
- `CueTable` 标题行已有「查找」；表格自身持有列宽、滚动及查找状态。顶栏为 44px，项目操作已多，窄屏横向滚动。
- `cue-cps.ts` 使用 Unicode 字素，忽略 ASS 块、空白、换行转义及标点，显示向下取整的 CPS。QC 应共享统计口径，阈值比较保留实际精度。
- `ass_format/codec.py` 是 ASS 支持范围和导出有效性的唯一权威。仅支持 b/i/u/s 的 0/1 标签和 N/n/h 转义；不能将 JASSUB 支持范围当成可导出范围。
- 普通导出与 App 离开前备份共用 `WorkbenchHandle.exportDraft`。新增普通导出预检不得破坏离页保护弹窗内的备份下载。

## 已确认并实现的 UI：字幕区右侧按需显示 QC

用户反馈：通常一条字幕不超过 25 字，下方右半区域较少使用；希望 QC 按钮位于查找旁，点击后在该区域显示可关闭的问题窗口。已按此方向确认并实施。

- 桌面打开后，下方区域为左侧现有字幕表 / 右侧 QC 问题列表，细边线分隔，两个列表独立滚动。共同沿用原有高度，不覆盖字幕，也不改变上方视频、频谱与编辑器。
- QC 目标宽度为下方可用宽度的 30%，限制在 320–480px；同时为左侧至少保留约 740px。当前默认非文本列总宽 376px，25 个中文在现有 13px 表格字号下约需 325px，其余预算用于内边距和滚动条。
- 当区域不足约 1060px，无法同时满足左右下限时，建议在同一区域切换显示 QC / 字幕表；关闭后恢复原表。以容器实际宽度判定，不把现有 900px 视频布局断点直接当成 QC 分栏断点。
- 例如 1440px 窗口下，区域约 1408px，QC 约 420px；1200px 窗口下，区域约 1168px，QC 约 350px；1024px 窗口建议使用切换显示。
- 首版不增加拖拽调宽、独立窗口或新持久化偏好。既有手动列宽继续保留；极宽列、ASS 原始标签或较长正文仍由表格原有换行/横向滚动处理。

已实现的交互：

- 初始「QC」；首次打开运行检查，显示「错误 N · 警告 M · 提示 K」。不预先显示虚假的 0。
- 每个问题显示严重度、字幕行号/时间、中文原因及测量值；问题整行可激活，不另设重复的定位按钮。
- 点击问题后保留 QC，上方切到对应字幕，同时在左侧字幕表选中并显示该行，可连续处理；再次点击 QC 或在 QC 内按 Esc 关闭，表格恢复可用宽度。窄屏关闭后显示对应行。
- 普通查找快捷键复用原查找；窄屏先切回字幕表。开关 QC 不重建 CueTable，保留列宽、查找和滚动状态。不新增默认 QC 快捷键，不占用 Tab、Enter 或试听按键。
- 修改文档后将结果和数量标记为待重新检查，旧结果不能继续被当成当前结果；提供「重新检查」。删除的字幕不保留可导航问题。检查请求需绑定文档引用，忽略迟到响应。
- 当前未提交时间草稿需明确提示；检查和导出均不隐式提交。首版建议以当前内存中已应用文档为检查对象，包含尚未保存到服务器的正文、样式及已提交时间修改。
- 普通导出先运行导出阶段 QC：无问题直接下载，有问题在同一 QC 区展示并提供继续导出；Warning/Info 不作为格式错误阻断。底层仍由原序列化器决定能否产出 ASS。备份导出保留原保护流程。

## 核心与规则

独立 `subtitle-qc` 纯模块依赖 `contracts` / `subtitle-model`，不依赖 React、DOM、HTTP 或工作区。工作区仅负责快照、检查生命周期、展示及导航。将可复用字符统计下移至 `subtitle-model`，原 CPS 列继续沿用显示口径。

公共输入为 `checkSubtitles(document, { phase, videoDurationMs, thresholds, formatIssues })`；输出问题包含 `id`、稳定 `type`、`cueIds`、`severity`、中文 `message` 和数值 `measurements`。文档级问题的 cueIds 允许为空，不能虚构所属行。UI 快照一致性由编排层负责，不把项目保存 revision 当作本地编辑版本。

默认规则（均集中为常量，无首版规则设置页）：

| 类型 | 默认判定 | 严重度 |
| --- | --- | --- |
| 非法时间 | 非有限值、负值、非法网格/支持范围或 start >= end，遵守既有格式契约 | Error |
| 时长 | 小于 500ms 或大于 7000ms | Warning |
| 重叠 | 时间相邻且同一样式，重叠超过 100ms 且超过较短行时长的 25% | Warning |
| 超出片长 | end 超出已知有限正片长；项目可使用既有媒体基准，本地使用已加载视频 | Warning |
| 空文本 | 去掉格式标签与空白后无可见正文；纯标点不当作空字幕 | 编辑 Info / 导出 Warning |
| CPS | 按已有字素口径，实际 CPS > 20 | Warning |
| 正文过长 | 计数字素超过 80 | Warning |
| 连续重复 | 同样式、相邻、非空可见正文相同，间隔 0–1000ms | Warning |
| 样式不存在 | style_id 不在当前文档样式中 | Error |
| 不支持的 ASS | 复用 codec 的实际校验结果 | Error |

重叠策略是保守的风险提示，不能推断叠字意图；不同样式的重叠不报告，可能漏掉需要人工核对的情况。重复判断保留标点和大小写，不进行语义相似判断。

ASS 支持性由后端 inspect_document 复用 codec 校验，已增加 POST /api/ass/inspect 无状态入口与 cue ID 定位；不在 TypeScript 复制第二套标签白名单/导出器，不修改保存模型和导出子集。每条字幕返回首个致命错误，文档级错误不虚构 cue ID。

排序复用既有时间顺序，避免两两全量比较。先测量现有 5000 事件上限的耗时；不预设 Worker、复杂增量计算或新依赖。

## 实测后的必要调整

5000 条问题首次完整渲染曾产生 325–503ms 主线程长任务、约 1.4 秒打开耗时。因此保留全部检查和计数，问题仅首批展示 100 条，按需继续显示；CueTable 缓存未变化的表格节点，事件仍显式读取最新回调。不引入列表框架或额外依赖。最终结果见验证记录。

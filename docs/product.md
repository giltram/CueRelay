# 产品需求与范围

状态：产品设计基线，2026-10-22；首个本地媒体 / ASS 有限切片已实现，实际范围及验证结果见 [架构入口](architecture.md) 和 [实验记录](experiments/media-ass.md)，下列完整协作要求尚未交付。根目录 `AGENTS.md` 已归档用户原文。

本文定义产品要求；实体见 [领域模型](domain-model.md)，技术方案见 [架构入口](architecture.md)，交付与实验见 [里程碑](milestones.md)。文中“要求”来自本次任务；“推荐”是可修改的设计基线；“待确认”尚不是承诺。

## 1. 目标与用户

CueRelay 面向小型字幕组，让打轴、翻译、校对围绕同一份字幕数据持续并行工作，减少 TXT/ASS 交接、合并和覆盖。它提供可实际使用的基础打轴能力，而不是完整 Aegisub 替代品。

主要用户是打轴人员、翻译人员、校对人员和项目管理员。工种是可叠加的权限预设，不是互斥身份；一个人可以独立完成一行，也可以只负责某一环节。项目是共享字幕文档的边界，已确认 P0 一个项目对应一个固定视频文件和一份 ASS 文档，不支持中途换片，不引入团队层级或工作流引擎。

产品成功首先看三人工序是否真正重叠，其次看数据安全、打轴效率、ASS 交付质量。分段包干不是主流程，也不要求先完成整个片段才流转。

## 2. 核心场景

1. 创建者选择本地视频，浏览器计算完整 SHA-256；项目只保存文件摘要、大小及必要媒体元数据。管理员添加成员并配置样式。
2. 三名成员分别在独立浏览器登录同一项目，选择各自本地文件，完成一致性校验。每个人独立播放、暂停、跳转。
3. 打轴人员用快捷键设置入点、出点并创建空行。服务端提交成功后，其他成员立即看到该空轴；不广播未保存的键入草稿。
4. 翻译人员获得行锁，填写译文并自动保存；显式“提交翻译”后，该版本进入待校对队列。打轴人员继续处理后续行。
5. 校对人员结合前后字幕与本地视频，批准或要求修改；也可按其编辑权限修改后重新提交、审核。审核始终指向明确版本。
6. 管理员检查空译文、待校对项与兼容性报告，导出统一样式的有效 ASS。无需文件合并。

## 3. 功能需求与优先级

| 编号 | P0：最小协作闭环的要求 |
| --- | --- |
| F01 | 登录、项目成员授权；服务端逐次鉴权；同一成员可有多个工种 |
| F02 | 本地选片、可取消且有进度的全文件校验、文件不匹配/不可播放提示；不上传媒体 |
| F03 | 播放、暂停、精确时间输入、前后微调、入点/出点、区间循环试听、字幕叠加与时间定位、基础快捷键及中文输入法兼容 |
| F04 | 创建空行、编辑时间/文本、删除、按时间浏览、上下文查看；允许重叠字幕 |
| F05 | WebSocket 实时显示已提交的新增、修改、删除、提交和审核；在线成员及占用提示 |
| F06 | 整行排他租约、自动保存、版本冲突提示、保存确认；断线后保留未提交草稿并可靠恢复共享状态 |
| F07 | 显式翻译提交；批准/要求修改；相关内容或样式变更后旧审核不再有效 |
| F08 | 项目预定义 ASS 样式、受权限控制的样式修改；普通成员只能引用样式，不能任意覆写项目字体/颜色/位置 |
| F09 | 支持明确 ASS 子集的导入、导出和兼容性检查；不支持的数据不得静默丢弃；不可编辑文件仍可获取原件 |
| F10 | 基础历史能定位修改者、时间、对象和前后值，包括删除；历史版本不覆盖当前版本号 |

F03 的最低体验必须经过熟练打轴人员试用。波形暂列 P1，但 [S1/S2 实验](milestones.md) 若证明没有基础波形就无法完成实际工作，则将有限的波形定位提升为 P0，并相应缩减外围功能。不能用时间戳输入框替代这项验收。可靠重连、错误提示与草稿保护已是 P0，P1 只增强体验。

| 优先级 | 内容 |
| --- | --- |
| P1 | 行评论、面向用户的历史恢复、拆分/合并、自动 QC、波形及更完善时间轴/快捷键、工作队列体验 |
| P2 | 独立无轴译文区、复杂任务分配/看板、高级 ASS 编辑、ASR、AI 翻译、团队权限与复杂流程 |

P0 不提供：多人同时编辑同一文本框、离线共同编辑与自动合并、共享播放进度、视频上传/转码/压制、任意片源时间轴映射、完整桌面编辑器、复杂特效制作。内部可保存离线草稿，但不能把它描述为离线协作。

## 4. 媒体使用与隐私

- 正常编辑路径只能发送字幕、权限数据、摘要和必要元数据；不得发送视频、帧图、音频、片段或波形采样。诊断、错误上报、第三方组件也受此约束。
- 完整 SHA-256 相等才视为本次所选文件通过字节一致性检查；大小/局部哈希只用于快速排除错误。每次重新选片重新验证，不凭同名同大小直接通过。
- 推荐校验前可查看共享字幕并本地试播，但禁用字幕修改/提交/审核；管理员管理成员与样式不依赖本地视频。校验失败不影响服务器已有字幕，也不禁止原件下载。
- 客户端哈希是协作防误用机制，服务器不接收文件，不能证明恶意客户端实际加载了什么，更不是登录或权限凭证。
- 不支持的编码应提示本地另行准备兼容文件。不能让每个人自行转码不同文件后继续宣称使用相同时间基准；更换项目基准片源需单独迁移方案，P0 不做。
- P0 使用标准文件选择器与本地 Object URL。刷新后可能需要重新选择；持久文件句柄是增强能力，不承诺无授权自动重开。

## 5. 非功能需求与可测目标

以下数值是推荐的 Alpha 验收预算，不是已验证性能。M1 记录测试硬件、浏览器、网络和样本后校准；调整需留下理由。

| 维度 | 目标及观察方式 |
| --- | --- |
| 正确性 | 已确认成功的修改在断网、重连、刷新、应用进程重启后可查；故障注入下不出现静默覆盖、重复执行或错误有效审核 |
| 协作延迟 | 3 人核心场景；扩展测试同项目 10 人、5,000 行、总计 5 次持久命令/秒持续 10 分钟，RTT ≤100ms；从数据库提交到其他活跃窗口应用的 p95 ≤500ms；尾消息丢失后 ≤10 秒发现并开始补齐 |
| 保存体验 | 暂定停输 500ms 合并一次保存；网络正常时最后一次输入到确认 p95 ≤2 秒；打字期间每 2 秒尝试保存最新有效草稿；未确认时始终有明确提示 |
| 本地性能 | 5,000 行采用窗口化列表；常用键盘操作响应 p95 ≤100ms。大文件哈希与波形的预算/阻断条件见 S1/S2 |
| 安全 | 跨项目访问与写入失败；撤权后新命令立即拒绝，旧连接最迟在 10 秒内停止接收项目内容；ASS/字幕不得成为 HTML、脚本或任意 URL 请求 |
| 媒体隐私 | 用合成文件抓取请求和日志，证明只有允许的元数据/字幕通过网络；媒体故障上报不含文件内容和本地路径 |
| 可维护性 | 模块依赖单向；业务规则由统一命令入口执行；重要不变量有反例测试；新 Agent 从架构入口可找到规则、入口和验收 |
| 运维可靠性 | 内部 Alpha 前演练数据库备份恢复，记录实际 RPO/RTO；未部署前不承诺 SLA，不能把日志当作备份 |

浏览器推荐先支持桌面 Chromium 的明确测试版本，Firefox/Safari 做兼容性评估后决定支持范围。Windows/macOS 的真实片源与设备矩阵尚待确认；手机编辑不是 P0 目标。

## 6. ASS 交付与审核语义

导入不是把外部样式自动覆盖到已有项目：P0 仅管理员向空项目导入一次，经预检接受样式与设置后形成项目统一样式；非空项目导入拒绝并提示新建项目。详细能力表及保真边界由 [领域模型](domain-model.md) 统一定义。

推荐提供“工作稿导出”和“交付导出”。工作稿显式标注含空译文/未审核项，仍输出语法有效 ASS；交付导出要求所有活动 Dialogue 有有效批准、无阻断兼容性问题。ASS 文件本身不携带平台的审核证明，另显示导出所用项目序号和样式版本。

P0 是单行审核，界面必须提供上下文；它不等于全片上下文审核。相邻行改变不自动撤销此行批准，负责人需在最终通看时复核。若要求“上下文任何变化都自动使批准失效”，须采用范围审核模型再调整当前基线。

## 7. 成功标准、已确认决策与验证项

M4 用三独立会话、同一视频完成至少 100 行：前 10 行已经翻译/校对时，后续行仍在打轴；无文件交接，所有已确认数据可恢复，交付 ASS 在 Aegisub 中正确打开并抽检显示一致。两名熟练打轴/校对人员完成真实片段试用，列出阻断问题并关闭后才能称为内部可用。

| 事项 | 当前决策或默认 | 后续验证 |
| --- | --- | --- |
| 真实片源与设备 | 已确认以字幕组真实片源的技术验证结果确定支持格式与浏览器矩阵 | M1 优先实测播放与实际打轴体验，不预先承诺任意格式逐帧 |
| 精度底线 | 沿用 10ms 时间坐标、精确跳转和试听的默认，逐帧/波形必要性通过打轴试用判断 | 先完成代表性片段，按真实阻断问题决定是否增加能力 |
| 基准片源 | 已确认一个项目绑定一个固定文件摘要，第一版不支持中途换片 | 验证本地加载与一致性，不设计换片迁移 |
| 审核粒度 | 已确认简单逐行审核、成员可兼任角色；沿用允许自审与人工最终通看的默认 | 在协作切片验证版本绑定，不增加双人或范围工作流 |
| ASS 输入边界 | 已确认优先覆盖实际使用的基础功能，不支持内容采取保护性处理 | S3 用真实样本核对现有能力表，按需补充基础支持，不扩展为完整 ASS 编辑器 |
| 使用规模与部署 | 私有小组、单区域、每项目约 3–10 人；管理员添加已有账号，P0 不发邀请邮件 | 影响认证入口、容量、日志保留和运维预算；不要求企业认证 |

## 已验证的回归

### R1 · [P2] 连续多行字幕的搜索定位会偏离目标

位置：`frontend/src/workspace-ui/use-cue-window.ts:82–84`，尤其是目标首次挂载时立即清除 `pendingReveal` 的处理。

复现条件与步骤：

1. 在隔离 API 夹具中加载 2000 条字幕，每条包含四次换行的文本，并带有唯一可搜索标记。
2. 在 1440 × 900 的 Chrome 页面中打开本地工作区和字幕查找。
3. 搜索第 1000 行的唯一标记，按 Enter 定位，等待布局稳定。

实际结果：列表显示第 1007–1010 行，目标第 1000 行完全不在可视区。观测到目标行纵坐标为约 −10.5 至 76.5px，而列表表头下沿为 609px、容器下沿为 887px。定位第 1500 行和第 400 行也复现了目标移出可视区。

原因：目标首次挂载后，布局 effect 只修正一次位置并清除定位请求。随后 ResizeObserver 更新实际行高，累计偏移、占位区域和挂载窗口再次变化，但没有继续保证目标可见。

影响：查找可以选中正确字幕，却无法把用户带到对应列表位置。QC 共用同一个 reveal 路径，因此也受该实现缺陷影响；本轮直接复现的是搜索入口。

建议：在实际行高更新后继续校正待定位目标，确认目标处于可视范围后再完成定位；补充连续多条变高字幕的搜索和 QC 定位回归。现有测试仅在首尾放置长文本，没有覆盖这一场景。

### R2 · [P2] 隐藏后恢复会丢失字幕列表阅读位置

位置：`frontend/src/workspace-ui/use-cue-window.ts:50–55`，尤其是容器宽度变化时无条件清空行高的处理。

独立于搜索的复现步骤：

1. 加载与 R1 相同的 2000 条多行字幕。
2. 将字幕列表滚动到 `scrollTop = 30000`，等待测量稳定。
3. 在同一标签页进入项目列表，使工作区隐藏，再通过浏览器返回恢复工作区。

实际结果：隐藏前显示第 865–868 行，恢复后显示第 882–885 行；两次 `scrollTop` 均为 30000。随后将窗口宽度从 1440 调至 1300，显示位置进一步变为第 887–890 行。

原因：隐藏使容器宽度变为零，触发全部行高缓存清空。累计高度重新使用估计值，但原像素滚动位置仍被保留，因此对应到不同字幕。实际宽度变化也会触发同类问题。

影响：用户返回工作区、调整窗口或改变列表布局时，正在阅读的位置会跳走，不能仅靠保留 `scrollTop` 恢复上下文。

建议：避免隐藏时因零宽度无效清空测量；实际布局变化需要重新测量时，以可见行 ID 和行内偏移保留滚动锚点。增加列表中段多行字幕的隐藏恢复和宽度变化测试；现有恢复测试停在第一行，未覆盖此问题。

## 优化背景和范围

2026-11-07 的第一阶段性能分析确认，大字幕表是主要可优化路径：单行编辑重新计算所有行的 CPS，普通播放使大量未变化文本参与渲染，搜索命中大量字幕时更新全部 DOM。音频已使用 Worker、分段读取和有界缓存，没有证据支持全局状态重构、新媒体 Worker、全片预计算或调整缓存预算。

| 编号 | 原问题 | 当前实现与状态 |
| --- | --- | --- |
| F1 | 未变化字幕行重复渲染、CPS 重算 | `CueRow` 按不可变 cue 和逐行显示属性 memo；CPS 只随正文与已应用时间计算。收益已验证。 |
| F2 | 大量搜索高亮更新全部 DOM | 超过 200 行使用变高窗口化，完整搜索/选择数据保留。性能收益成立；R1–R3 原场景已修复，仍需处理 R4。 |
| F3 | 持续输入触发完整 ASS 快照转换并取消中间请求 | 未优化调度。保留原 120ms debounce、取消/版本和非法草稿保护；16 字慢速输入仍有 16 次转换。需先取得真实网络下的最终有效画面延迟证据。 |
| F4 | Worker 缓存命中仍重复发送 tile，显示 Canvas 缓存失效 | UI 声明当前持有的 tile 与 spectrum 能力，Worker 只发送缺失/升级数据，保留对象身份以复用 WeakMap 图像。已有功能与分配量验证。 |
| F5 | 暂停、隐藏后仍持续 RAF 和 DOM 写入 | 仅可见播放/试听持续 RAF；暂停 seek、视窗变化、恢复等离散刷新，值未变不写 DOM。已有浏览器验证。 |

R3 独立复现中的关键结果：200 行模式滚到 `scrollTop=1000`，可见 ID 为 `new-12` 至 `new-16`；撤销到 201 行后 `scrollTop=1033`，仍显示同一批 ID。仓库测试同时确认首行 `new-12`、行内偏移 43px 不变。恢复一行会改变像素位置，验收应比较阅读行及偏移，而非要求 scrollTop 数值相同。

## 待修复 R4 · [P2] 删除阅读锚点本身时，跨阈值交接失效

位置：[use-cue-window.ts](../../frontend/src/workspace-ui/use-cue-window.ts)，检查时第 72–76 行清理删除的锚点，第 94–95 行重新读取锚点，第 112–115 行执行恢复。

### 可复现步骤

1. 本地工作区加载 201 条字幕，每条间隔 3000ms、持续 2400ms，使用同一有效 style_id，ID 为 `new-0` 至 `new-200`。第 i 条文本采用 `target${i + 1}end ` 加四次 `多行文本与换行测试\n`，形成连续多行文本。
2. 使用 1440×900 的 Chrome 页面。打开查找，输入 `target100end` 并按 Enter，选中 `new-99`。
3. 在字幕列表内继续滚动，使该行成为首个可见行，顶部约 20px 位于 sticky header 后方。它必须是阅读锚点，而不只是选中行。
4. 将焦点放到工作区 main，按 `Control+Delete` 删除该行，列表从 201 行变成 200 行。
5. 等待约 300ms，检查首个可见 ID 以及紧邻后继 `new-100` 的位置；再撤销一次观察恢复。

可以在隔离浏览器探针中用以下几何操作精确完成第 3 步（不改业务数据）：

```js
await page.locator('.table-scroll').evaluate(container => {
  const row = container.querySelector('[data-cue-id="new-99"]');
  const header = container.querySelector('thead');
  container.scrollTop += row.getBoundingClientRect().top
    - header.getBoundingClientRect().bottom + 20;
});
```

### 实际证据与影响

| 阶段 | scrollTop | 可见 ID |
| --- | ---: | --- |
| 删除前 | 5069 | `new-99`、`new-100`、`new-101`、`new-102` |
| 删除后，原生 200 行 | 5069 | `new-58`、`new-59`、`new-60`、`new-61` |
| 再撤销，窗口化 201 行 | 5069 | 仍为 `new-58` 至 `new-61` |

删除后后继 `new-100` 的顶部在约 4153.5px，而列表可视区位于约 609.5–887px，完全离屏。用户删除正在阅读的字幕后，会丢失相邻编辑上下文；这不是允许的像素偏移微调。

### 原因与建议

被删除的 ID 恰好是阅读锚点，清理 effect 将其设为 null。后续布局 effect 从已经展开为原生全量表格的 DOM、沿用的旧像素 scrollTop 读取新锚点；估算占位高度已变为真实行高，此时读到的是远处行，恢复逻辑随即接受该错误位置。

建议在原锚点被删除时，根据变更前行顺序选择仍存在的相邻行作为交接目标（例如优先后继，无后继再前驱），再完成模式切换；不要仅在新布局中按旧像素位置重新猜测。具体实现应保留模块边界，不把滚动状态写入编辑历史或依赖工作区的私有选择状态。

先把此场景加入 `cue-window-threshold-checks.mjs`，验证删除前后的相邻内容连续性及撤销行为。现有 R3 测试删除的是离屏第一行，阅读锚点仍存在，所以全部通过也无法覆盖 R4。修复时可一并覆盖批量删除包含锚点、无后继/空列表等相邻边界，避免只针对一个 ID 打补丁。

## 当前模块边界与关键文件

- `CueTable → CueRow`：表格编排、逐行 memo。事件回调读取最新工作区处理函数，避免旧文档闭包；选择、播放、高亮、样式、行号均需保持正确。
- `CueTable → use-cue-window → cue-window`：只拥有 DOM、行高、挂载窗口、阅读锚点与定位。纯函数负责累计偏移、窗口、锚点恢复和最小 reveal。阈值仍为 >200，缓冲前后各 8 行，另保留焦点/校正需要的少量行。
- 搜索、Shift 选择、剪贴板、QC、导出都消费完整字幕数据，不能因窗口化只处理已挂载行。
- `media/audio/use-audio-analysis` 与 `audio.worker`：复用限定同一 File/Worker 与固定分析参数；UI 只保留当前视窗相交 tile，模式升级仍发送 spectrum。不得 transfer Worker 唯一缓存或新增无界 Map。
- `AudioTimeline`：读取视频/独立试听时钟；仅可见播放期间持续 RAF，暂停和恢复采用离散刷新。PCM、FFT、字幕持久化所有权没有移入 UI。

# 本机工作区草稿恢复代码审查

审查提交为 `d901708`（`add local workspace draft recovery`），对比父提交 `53709d8`，范围为该次提交的 36 个文件。建议优先修复下列三项 P2，其中两项会丢失已输入的时间，一项会在用户明确放弃后留下字幕副本。另有两项 P3，涉及过期的恢复入口和持久化文档。

## P2 · 有字幕但未选行时，输入的时间未进入草稿

打开已有字幕的项目并验证片源，保留初始的未选行状态。此时入点框可以编辑。实测填入 `0:00:01.23` 后触发离页写入，IndexedDB 中仍有 0 条草稿。刷新后入点回到 `0:00:00.00`，页面没有恢复入口。

`unappliedTiming` 第 15 行要求存在选中行或字幕列表为空。对于有行但未选行的项目，这个条件直接丢弃了原始输入。草稿模型已经允许 `cueId: null`。建议以未选行时实际显示的初始值判断输入是否变化，并保留未选行状态。现有项目回归在验证视频时会顺手选中第一行，需要单独覆盖先输入时间、再刷新的操作顺序。[时间草稿提取，第 10–16 行](../../frontend/src/workspace-ui/use-workspace-draft.ts) · [现有测试辅助函数，第 19–22 行](../../frontend/regression/workspace-drafts.spec.mjs)

## P2 · 空项目恢复一次后，把出点改为零会删除草稿

空项目初始出点为 `0:00:02.00`。实测将其改为 `0:00:01.00`，等待保存，刷新并恢复，能正确看到 1 秒。重新验证片源并把出点改为 `0:00:00.00` 后，IndexedDB 记录数从 1 降到 0。再次刷新时显示 2 秒，用户输入的零出点丢失。

恢复时 `withSelection` 把空选择写成 `[]`。第 240 行仅在草稿出点恰好等于重置后的零出点时才把它改回 `undefined`。后续判断又用这个选择字段区分初始的 2 秒和删完最后一行后的 0 秒，于是把下一次输入的零误判为恢复默认值。建议显式保留无选中行时的时间基准，并分别测试「初始空项目」和「删除最后一行」在恢复后继续编辑、再次刷新的结果。[恢复逻辑，第 234–244 行](../../frontend/src/workspace-ui/EditorWorkbench.tsx) · [基准判断，第 11–16 行](../../frontend/src/workspace-ui/use-workspace-draft.ts)

## P2 · 退出组织成功后，设置刷新失败会跳过草稿删除

在同一标签页保留带草稿的工作区，进入组织设置，选择「退出此组织」并点击「明确放弃并继续」。在浏览器测试中让退出请求成功，再让紧随其后的个人设置 GET 失败。此时编辑器已经卸载，确认框仍显示错误，IndexedDB 中仍能读出刚才明确放弃的字幕正文。

`onLeave` 在退出成功后立即清除工作区，随后等待 `loadContext(true)`。`execute` 把草稿删除放在整个 action 成功返回之后，因此附带的设置刷新失败也会跳过删除。建议以退出成功且工作区已清除作为删除时点，单独报告设置刷新错误。回归应验证退出请求失败时保留草稿，以及退出成功而后续刷新失败时删除旧工作区的活跃记录。[切换与删除，第 201–210 行](../../frontend/src/App.tsx) · [退出组织，第 290–295 行](../../frontend/src/App.tsx)

## P3 · 另一标签页放弃草稿后，旧页面仍能导出已删除的快照

关闭持有本地草稿的标签页，再用同一账号打开两个工作区页面，让两页都显示这份候选草稿。在 A 页点击「放弃草稿」后回到 B 页，点击「恢复草稿」会报错，但按钮仍在。实测再点「导出草稿 ASS」，下载文件仍包含已删除草稿的正文。

候选列表只在工作区挂载时读取。恢复和放弃操作会检查其他标签页记录的归属与版本，导出则直接使用页面缓存的 `record.document`。建议在操作时按记录 ID 核对当前版本和归属，发现记录已删除或已转移就移除旧候选。可用上述双页顺序验证恢复、放弃和导出对过期记录的处理一致。[候选读取，第 35–42 行](../../frontend/src/workspace-ui/use-workspace-draft.ts) · [草稿导出，第 598–602 行](../../frontend/src/workspace-ui/EditorWorkbench.tsx)

## P3 · 项目说明仍称本地字幕只保存在内存

项目契约第 27 行介绍了自动保存，同页第 31 行却写着「它的字幕仍仅在内存」。根 README 第 60 行也仍称「没有实时协作或自动保存」。读者据此可能误以为关闭页面就会清除本地字幕副本。建议两处统一说明浏览器会保存可恢复的 IndexedDB 副本，项目提交和独立 ASS 文件仍分别通过「保存项目」和「导出 ASS」完成。[项目契约，第 27–31 行](../projects.md) · [根 README，第 58–60 行](../../README.md)

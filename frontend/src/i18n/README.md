# Presentation language

The public entry point is `index.ts`: `t` for render-time strings, typed `msg` for retained UI feedback, and `formatMessage` for descriptors and errors. `react.tsx` subscribes through react-i18next; `useMessageState` retains the original descriptor/Error and formats it at each render. `LanguageSelector` is a direct control, with immediate application and an inline retry if account persistence fails.

`shared/languages.json` owns product locale IDs, native display names, browser matches, handbook filenames and the single fallback. `registry.ts` derives the supported types/menu/resources; JSON under `locales/<locale>/<module>.json` follows existing modules. i18next handles interpolation and locale-specific plural categories. `en-XA` is generated from English only in dev/test; it is never persisted to accounts or exposed in production. No remote translations, locale routes or extra translation platform.

Preference ownership: an authenticated account uses `PersonalSettings.language_preference` through the existing partial PATCH endpoint. Anonymous selection has its own `cuerelay.anonymous-language` localStorage key. A real choice wins over System; System negotiates ordered `navigator.languages`, then falls back to Simplified Chinese. `languagechange` renegotiates System. Account ID and request sequence fence optimistic/pending choices and replies, including returning to a prior account. Anonymous choices are never copied into an account. No subtitle data is stored here.

App owns settings snapshot ordering: accepted PATCH callbacks contain only the fields written by that operation and advance those fields' in-memory versions. `loadContext` captures the versions before reading, hydrates untouched fields, preserves fields written since the read began, and completes settings readiness even on the initial load. Later reads accept remote changes normally. This complements the hook's account/PATCH sequence fence.

The language hook owns one account-scoped choice with an explicit phase. `pending` and `failed` retain the optimistic preference (and failure/retry feedback); `transient` retains the development pseudo language without persisting it. `saved` uses the returned server preference only while settings are not ready. As soon as ready is true, rendering uses App's saved preference immediately and an effect clears the completed choice, without requiring the two values to match. A newer remote preference can therefore complete initialization and replace a successful local choice. Cleanup only removes the same completed choice, never a later selection. Controlled initial GET, remote refresh, failure/retry, GET/PATCH and disjoint PATCH order regressions live in `browser-tests/{workspace-review-regressions,settings-response-races}.mjs`.

The translation instance has a stable `t` identity. Subscribe in presentation components; do not put a changing translator in effect dependencies. Locale is absent from workspace keys, history, media/File/handle ownership, Object URLs, Workers, preview documents and renderer-session effects. Lists keep measured user-content rows; normal ResizeObserver/DOM anchor handling accounts for translated header geometry. Menu positioning remeasures translated text; internal menu scrolling stays open.

Pure validators, QC, codecs and controllers depend only on `contracts/messages`. They return descriptors or `MessageError`, never import this module or React. `contracts/message-keys.ts` and `resource-types.ts` are generated by `npm run i18n:types`; `t`, `msg` and `describe` check keys. Dynamic network reasons are resolved only at the presentation boundary and retain exact legacy text when unknown. `errorMessage` carries structured-clone-safe descriptors across Workers. See [the full maintenance and acceptance workflow](../../../docs/internationalization.md).

Dependencies: `{App, page/account/project/style/glossary/workspace/media/preview presentation} → i18n → {contracts, shared registry, i18next, react-i18next, React}`. The preference hook depends only on the injected `JsonRequest`, not account UI internals. Shortcut presentation imports the shared contract, never the workspace implementation.

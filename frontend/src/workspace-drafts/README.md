# 本机工作区草稿

IndexedDB 中的草稿只供恢复编辑。当前字幕仍由 `workspace-ui/use-edit-history` 管理，已提交项目仍以服务器快照为准。

- `model.ts` 定义版本化草稿。记录包含账号/组织/项目范围、标签页 ID、记录 ID、写入代次和时间、项目基准 revision（本地工作区为 null）、现有 ASS DTO、可选未应用时间及对应行 ID。未选行的时间输入同时记录默认出点 `unselectedEndMs`，用于区分初始的 2 秒和清除选择后的 0 秒。旧记录仍可读取，工作台根据草稿与服务器快照是否相同推断时间基准，并保留原始输入。本地空白工作区的纯时间草稿带 `localTimingOnly`，恢复时沿用该空白文档基准。缺少该标记的旧本地草稿按含字幕内容的草稿保留。样式、脚本设置、原始 ASS 模板和行元数据都来自原 DTO。媒体、播放状态、多选和撤销栈留在原模块。
- `tab.ts` 用 sessionStorage 保留刷新时的随机标签页 ID，用同源 Web Locks 对 ID 排他占用到文档关闭。复制标签页带入的旧 ID 无法占用时生成新 ID。候选操作以共享模式获取来源 ID 的锁，可相互并行，并与来源标签页的排他占用互斥。
- `store.ts` 拥有数据库 `cuerelay-workspace-drafts` 和事务。记录以独立 ID 为主键，按范围查询。恢复、放弃和导出候选时按 ID 核对范围、归属和写入代次。恢复转移记录归属，放弃删除精确记录，两者的核对和修改由 IndexedDB 写事务串行执行。导出使用校验通过的快照。记录已失效或来源标签页持有排他锁时，工作台撤下旧入口。
- `autosave.ts` 只写工作台正在编辑的一个记录，尾部延迟 750ms，连续输入最多等待 3 秒。事务按创建顺序执行，代次检查防止旧回执覆盖新状态。确认提交后清理当前已持久化的版本，仍有新输入则按新 revision 写入。隐藏页面、离开页面和显式项目保存开始前会尽力提交待写入快照。失败保留内存编辑，也保留最后一次成功的磁盘记录。

依赖为 `{main, App, workspace-ui} → workspace-drafts → contracts/subtitles + 浏览器 API`。main 在账号或项目请求前认领标签页 ID。工作台 `use-workspace-draft` 负责 React 生命周期和读取候选，`WorkspaceDraftNotice` 负责双语状态及操作。项目恢复前由 app-workspace 重新读取服务器 revision，工作台同时检查草稿和当前保存基准。冲突草稿继续可导出，选用已加载版本仅收起入口。退出组织成功并清除工作区后，App 先尝试删除明确放弃的活跃记录，再刷新个人设置和组织列表。删除失败时仍刷新，并保留本机操作错误。

批量时间平移的已应用时间随现有字幕 DTO 保存和恢复。恢复沿用草稿的既有历史基线规则，项目确认显式保存后清理对应的本机副本。回归见 `frontend/regression/time-shift.spec.mjs`。

浏览器清理站点数据、存储权限、配额和异常退出会影响可恢复范围。崩溃前尚未完成的事务可能丢失。草稿目前保留到明确放弃或确认提交，不进行基于时间的自动清理。ASS 导出下载不会清除草稿。回归入口见 `autosave.test.ts` 和 `frontend/regression/workspace-drafts.spec.mjs`。
